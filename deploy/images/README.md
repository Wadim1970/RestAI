# Фото блюд → своё хранилище Supabase

Скрипт `upload-dish-images.mjs` берёт фото из папки на сервере, находит блюдо по
названию файла, делает две версии (800×800 для карточки блюда и 300×300 для меню,
подсказок и голосового помощника; WebP, прозрачный фон, пустые поля обрезаны),
загружает их в Supabase и прописывает ссылки в меню.

## Где лежат файлы

```
menu-images/                         ← хранилище (bucket), открыто на чтение
  <id ресторана>/dishes/
    <id блюда>_<хэш>.webp            ← 800×800, image_url
    <id блюда>_<хэш>_thumb.webp      ← 300×300, image_url_thumbnail
```

Имя по id блюда: без кириллицы, не ломается при переименовании блюда. Хэш меняется
вместе с картинкой — при замене фото гости не застрянут на старом из кэша.
Блюдо в двух разделах («Популярное» и «Пицца») получает одну картинку.

## Как загрузить

1. Назвать файлы как блюда в меню: `Джин Bombay Sapphire.png`, `Коньяк Napoleon.jpg`.
   Регистр, «ё» и знаки препинания не важны.
2. Скопировать папку на сервер, например в `/opt/restai/uploads/alco`.
3. Один раз поставить зависимость:
   ```bash
   cd /opt/restai/RestAI/deploy/images && npm install
   ```
4. Просмотр (ничего не загружает):
   ```bash
   node upload-dish-images.mjs --dir /opt/restai/uploads/alco --section "Алкогольные напитки"
   ```
5. Если сопоставление верное — то же самое с `--go`.

Параметры: `--restaurant <id>` (по умолчанию Сыроварня), `--section` (искать блюда
только в разделе), `--env` (файл с SUPABASE_URL и SUPABASE_SERVICE_KEY, по умолчанию
`/opt/restai/Waiter-app/.env.production`).

# Видео блюд (окно подробного описания)

Вместо фото в окне блюда гость видит короткое видео. Нет видео, оно не загрузилось
или у гостя включена экономия трафика / нет скорости — остаётся фото.

## Требования к файлу

| Что | Значение |
|---|---|
| Контейнер, видео | MP4, видео **H.264** (`yuv420p`) |
| Кадр | вертикальный **9:16**, лучше 540×960 (хватит 480–720 по ширине) |
| Звук | **без звука** |
| Длительность | 5–6 секунд (допустимо до 8; больше 15 — не принимается) |
| Размер | ориентир до **2 МБ**, жёсткий предел 5 МБ |
| Кадров в секунду | 24–30 |
| «Быстрый старт» | обязательно (`moov` в начале файла), иначе видео не начнёт играть, пока не скачается целиком |

**Частая ловушка:** видео с камеры iPhone пишется в HEVC (H.265) и часто в 10 бит/HDR —
на части телефонов гостей оно не воспроизведётся. Скрипт такой файл не пропустит и скажет
почему. Приведение любого видео к нужному виду одной командой (подставьте свои имена):

```bash
ffmpeg -i исходное.mov -vf "scale=540:960:force_original_aspect_ratio=increase,crop=540:960,fps=30" \
  -c:v libx264 -profile:v main -pix_fmt yuv420p -crf 26 -maxrate 1500k -bufsize 3000k \
  -an -movflags +faststart -t 6 "Борщ.mp4"
```

Проверено: исходник HEVC, 10 бит, 60 кадров/с, 10 секунд, со звуком, 7 МБ → 0,3 МБ,
проходит проверку без замечаний. На реальной съёмке еды файл выйдет тяжелее (обычно
0,5–1,5 МБ) — это нормально.

## Где лежат файлы

```
menu-videos/                         ← хранилище (bucket), открыто на чтение, только MP4, до 5 МБ
  <id ресторана>/dishes/
    <id блюда>_<хэш>.mp4
```

Ссылка прописывается в `menu_items.video_url` (целиком, как `image_url`): при переезде на
другое хранилище или CDN меняется только адрес в ссылках, приложение не переписывается.
Блюдо в двух разделах («Пепперони» в «Популярном» и в «Пицце») получает одно видео.

## Как загрузить

1. Один раз применить миграцию `20261104010000_menu_item_video.sql`.
2. Назвать файлы как блюда в меню: `Борщ.mp4`, `Пепперони.mp4` (регистр, «ё» и знаки не важны).
3. Скопировать папку на сервер, например в `/opt/restai/uploads/video`.
4. Просмотр (ничего не загружает, но проверяет каждый файл):
   ```bash
   cd /opt/restai/RestAI/deploy/images
   node upload-dish-videos.mjs --dir /opt/restai/uploads/video
   ```
5. Если всё верно — то же самое с `--go`. Файл с ошибкой не загрузится, с предупреждением
   («тяжёлый», «есть звук») загрузится, но вы это увидите. Ключ `--fix` без потерь
   исправляет только отсутствие «быстрого старта».
6. Убрать видео у блюда (останется фото): `node upload-dish-videos.mjs --remove "Борщ" --go`.

Для проверки файлов нужен `ffprobe` (`apt install ffmpeg`); без него скрипт проверит только размер и
«быстрый старт». Параметры те же, что у загрузки фото: `--restaurant`, `--section`, `--env`.
